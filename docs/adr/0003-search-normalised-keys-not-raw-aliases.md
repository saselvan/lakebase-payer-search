# Search normalised, de-duplicated keys instead of every alias row

The alias table has millions of rows, but most are near-copies of the same name (group numbers, case, punctuation). Searching every row made trigram matching score hundreds of thousands of near-copies per query (6–19 s, over the Data API's 8 s timeout), and the top candidates filled up with copies of a few payers, so later pages came back empty. We normalise each alias (lowercase, drop digit runs of 4+, punctuation to spaces) and keep one search key per Payer per normalised form: 3 M rows become about 33 k keys and a search takes milliseconds. The alias table stays the source of truth. If a real corpus has millions of genuinely distinct forms, the fallback is a GiST trigram index with nearest-first ordering on the full table (built and measured, not the default).
