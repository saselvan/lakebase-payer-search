# Search-quality flywheel — first run (2026-10-06)

Method: `scripts/run_quality_job.py` → one serverless notebook job (`jobs/quality_flywheel/flywheel_notebook.py`)
in the AWS us-east-1 demo workspace. All search calls went to the **live** Lakebase Data API as the service
principal (10 concurrent requests). Corpus: 3,000,000 synthetic alias rows, 6,291 payers, 117 brands.
FM: `databricks-claude-sonnet-4-5` via `ai_query`, one call per brand, cached in UC `fm_payer_proposals`
(117 of 117 parsed, 0 errors). Nothing was applied to the live index.

## Why the 172 FM misses happen (sampled by hand, 25 of 172)

| Cause | Examples (query → top hit) | Fix |
|---|---|---|
| Overlapping brands in the synthetic seeds: "Anthem Blue Cross" exists in every state *and* each state has its own "Blue Cross and Blue Shield of X" | `blue cross idaho` → Anthem Blue Cross EPO - ID | Data, not search: real payer lists have one Blue licensee per state. Fix the seeds. |
| Names the corpus does not hold (former names, parent or program names) | `wellmark` (BCBS Iowa), `champus` (TRICARE), `providerone` (Apple Health), `mohawk valley` (MVP) | Synonym candidates (below), or add these as aliases. |
| Misspellings more than 1 edit per 3 letters away | `atena`, `athem`, `acchs`, `ambeter health` | Synonym candidates: 175 one-word misspellings proposed. |
| Two-letter initials | `mh` (MassHealth), `hn` (Health Net) | Leave as is: too short to mean one payer. |
| Brand word shared with many plans | `magellan complete`, `humana gold` → plan names with "Complete"/"Gold" | Ranking: weight brand words over plan words (open). |

10 of 172 misses returned no result at all. 9 contain a state code.

Worst brands (FM brand@10): Anthem Blue Cross and Blue Shield 0.25, Magellan Health 0.25,

## Gate (report only)

- FM proposals: 1,166 items were multi-word (dropped: the tokenizer maps one word to one lexeme).
- One-word proposals dropped by the safety rules: already a synonym 61, a real corpus word 43,
  shared by two brands 30, shorter than 3 letters 12.
- **287 candidates passed**: 175 misspellings, 93 abbreviations, 10 card text, 9 former names.
  File: `results/synonyms_fm_candidates.csv`, and UC table `fm_synonym_candidates`.
- **37 of the 172 FM misses contain a candidate word** (for example `atena`, `athem`, `acchs`,
  `providerone`, `aaa`, `bcbsm`). Applying the candidates should fix most of these 37; rerun to prove it.

To apply: review the CSV, copy good rows into `data/seed/synonyms.csv`, run `SKIP_DATA=1 scripts/setup.sh`,
rerun the job, and keep the change only if both brand@10 numbers and MRR hold or rise.

Caveat on circularity: the FM wrote both the misspelling candidates and the FM queries, so "candidate fixes
FM miss" is partly the model agreeing with itself. The rule set and, later, real Search-log queries are the
independent checks.

## What your application's search log adds later

`audit.search_log` already records Tenant, query, result count and time per search. With the picked result
added, your real users become the synonym source: queries that end on the same payer are synonyms
(click-graph mining), and a query retyped within seconds is a correction (reformulation mining). Those pairs
replace the FM in the propose step, and the same validate → evaluate → gate loop applies.
